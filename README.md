# dsh-plugin-masterprompt(人设配置)

> 这是 [lw-storm/dsh-plugin-masterprompt](https://github.com/lw-storm/dsh-plugin-masterprompt) 的 fork。
> 在它的基础上加了**参考图**:一个人设模板可以绑最多 4 张图片,图片本体连同手写描述
> 一起发给模型(而不是只发一段文字描述)。其余行为与上游一致。

为 DeepSeek Harness 增加"人设 / master prompt"能力:在输入框工具行(标准模式选择器旁边)
常驻一个「人设」小框,点击展开后可**新建、编辑、删除、切换**人设模板,当前对话的后续回复
立即按所选人设走。

## 特性

- **最高优先级注入**:人设文本插入在系统提示最顶部(排在 DSH 身份声明之前),模型第一眼看到。
- **固定交互条款**:人设文本之前会自动附加一段不可覆盖的固定规则——向用户提问必须用
  `ask_user_question` 可点选卡片(带建议选项);人设里的提问要求(追问到底、一次一问、附建议答案等)
  只约束提问的节奏与内容,不改变提问的呈现方式。
- **参考图**:一个人设模板可以绑最多 4 张图片。图片本体和手写描述会一起发给模型,模型能真的"看见"。
- **只影响当前对话**:按 `sessionId` 隔离,其他对话不受影响。
- **修改立即生效**:切换/编辑后,当前对话下一轮回复即按新人设(正在生成的回复不回溯)。
- **子代理继承**:当前对话派生的子代理继承该对话的人设(沿 parentSession 谱系)。
- **新对话继承上次人设**:新对话默认沿用最近一次选用的人设;显式切回"标准模式"则新对话默认也回到标准模式。
- **删除保护**:正在被任何对话使用的模板禁止删除。
- **重启保留**:模板库与各对话的选择状态存于本地 JSON,重启 DSH 后依然生效。

## 安装

```sh
dsh plugin --profile web add <本目录绝对路径>
```

然后**重启 DSH** 生效(插件行与客户端 bundle 在启动时加载)。

## 使用

1. 在任意对话的输入框工具行左侧找到「人设 · 标准」小框(实心绿点 = 当前对话有人设)。
2. 点击小框展开面板:
   - **新建人设**:填写名称 + 纯文本(思考模式、缓存策略、提问模式、语气、边界等自由编写,上限 100000 字符)。
   - **参考图**:在编辑框里选图(PNG / JPEG / WebP / GIF,单张 ≤ 8MB,每模板 ≤ 4 张),
     每张图可以写一段**手写描述**;描述会紧挨着图片一起发给模型。
   - **应用**:点选模板立即切换到该人设。
   - **编辑**:修改模板文本,所有使用它的对话立即用新文本。
   - **删除**:使用中的模板按钮置灰,需先切换才能删除。
   - **恢复标准模式**:清除当前对话人设(新对话默认也回到标准模式)。

## 参考图是怎么进模型的

- 图片本体走 DSH 自己的附件通道:插件把字节交给 `ctx.attachments`(校验、归一化、按内容寻址落盘),
  适配器在每次请求里把它投影成模型能收的请求版本。
- 参考图以**一条 user 消息**的形式挂进会话历史(内容 = 说明文本 + 图片块 + 说明文本 + 图片块),
  之后每轮请求都会重新带上这张图——和舰长自己粘贴图片走的是同一条路径。
- **模型不支持图片时**(路由没有声明 image 输入、或附件服务不可用):只发描述文本,图片本体不发,
  请求永远不会因为图片失败;模型若明确拒绝图片,插件会自动改为纯文字并重试一次。
- **换图/换人设**:会话里那条参考图消息会被就地替换,不会出现新旧两张图并存。
- **恢复标准模式**:那条消息会被替换成一句"参考图不再随请求发送"的说明,图片不再消耗 token。
- **第一轮**:新会话的第一轮请求里,会话表面还没有 system 消息,参考图这时不能落盘(DSH 要求会话表面
  必须以 system 消息打头,抢在前面会让整份日志在下次加载时报
  `system/message requires a protected first surface head`)。所以第一轮只把参考图挂进那一次请求,
  不写进历史;等 system 消息落好之后,再落一条持久的参考图消息。
- **代价**:每轮请求都带一张图,等于每轮多付一次图片 token。介意的话就别绑图,或者只写描述。

## 示例人设

见 [examples/persona-whale-girl.md](examples/persona-whale-girl.md)——一份「可爱外壳 + 专业内核」的鲸鱼娘编程助手模板,可直接粘贴使用,也展示了写人设的基本结构(角色设定 → 说话风格 → 工作模式 → 技术要求 → 边界)。

## 数据存储

- 状态文件:`%DSH_HOME%\dsh-plugin-masterprompt\state.json`
  - `templates` 模板库(含 `images` 参考图元数据);`selection` 各会话选择表;`defaultPersonaId` 新对话默认人设。
- 参考图原始字节:`%DSH_HOME%\dsh-plugin-masterprompt\images\<图片 id>.<ext>`;
  `state.json` 里只放元数据(名称、格式、字节数、描述、文件名)。
- 模型侧的 durable 附件在 DSH 自己的附件目录里(内容寻址),插件不复制它。
- 损坏的状态文件会自动备份为 `state.json.corrupt-<时间戳>` 并重建。

## 卸载

```sh
dsh plugin --profile web remove dsh-plugin-masterprompt
```

重启 DSH 后生效。可选:手动删除 `%DSH_HOME%\dsh-plugin-masterprompt\` 目录清空所有人设数据。

## FAQ

**Q: 切换人设后,正在生成的回复会变吗?**
A: 不会。人设在下一轮回复起生效,正在生成的内容不回溯。

**Q: 子代理会用主人设吗?**
A: 会。当前对话派生的子代理沿 parentSession 谱系继承人设。

**Q: 为什么我的人设里写了"逐条追问",AI 却用卡片提问?**
A: 固定交互条款的优先级高于人设文本:提问必须渲染成 `ask_user_question` 可点选卡片。人设只能约束提问的节奏与内容(比如一次只问一个、附建议答案),不改变呈现方式。这是刻意的防呆设计。

**Q: 人设会影响 token 消耗吗?**
A: 会。人设文本会完整注入每轮系统提示,长度与 token 消耗成正比。建议日常人设控制在千字以内;示例模板(鲸鱼娘)约 800 token,已算比较饱满。参考图更贵:每轮请求都会重新带一遍图片,一张图按几百到上千 token 计。

**Q: 参考图会出现在对话记录里吗?**
A: 会。它以一条 user 消息的形式挂在会话历史里(带「人设参考图」标记),所以在聊天窗口里能看见它,
也能在历史回放里看到。这是有意的:DSH 的请求体来自会话历史,只有留在历史里的图片才会每轮都被带上。
换人设或恢复标准模式时,这条消息会被就地替换,不会新旧并存。

**Q: 图片描述是自动生成的吗?**
A: 不是,描述由使用者手写。插件不做任何模型调用来生成描述,避免多一次请求和一次费用。

**Q: 支持哪些图片格式?**
A: PNG / JPEG / WebP / GIF,单张 ≤ 8MB,每个模板 ≤ 4 张。格式由字节本身判定,不看扩展名。

**Q: 多个对话能用不同人设吗?**
A: 可以。人设按 `sessionId` 隔离,每个对话独立选择,互不影响。

**Q: 状态文件损坏了怎么办?**
A: 插件会自动把损坏文件备份为 `state.json.corrupt-<时间戳>` 并重建空状态,不会丢掉备份,可手动抢救。

## 安全提示

人设文本是**最高优先级指令**,由使用者自担:若与 DSH 系统规则冲突(如要求忽略工具规则),
可能让 AI 行为异常。插件不做任何审查或拦截。
